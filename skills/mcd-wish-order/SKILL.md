# 麦愿单（许愿式点餐）

## 什么时候用

用户表达了一个**模糊的用餐愿望**，而不是精确的点餐指令。例如：

- 「今天被领导骂了，想吃点治愈的，别超过 30」
- 「明天带三个同事吃饭，不想显得抠，也不想超预算」
- 「减肥第三周，馋得不行，给我找个能骗过自己的」
- 「加班到现在很饿，想吃饱一点，不吃辣」

不适用：用户已经明确说「我要一个巨无霸套餐加中可」，那是下单执行，不是许愿。

## 怎么做

### 第 1 步 · 拆愿望，别追问

把用户的话翻译成四个字段：**预算 / 人数 / 餐段 / 口味倾向**。

关键规矩：

1. **不要弹选项让用户选**。缺什么就按常识补，然后告诉用户你补了什么。
2. 每个字段标来源：`你说的` / `我推断的` / `我替你定的（可以改）`。
3. 否定句式要单独处理：「不吃辣」是排除，「不想显得抠」是要体面，按字面匹配会反。

输出示例：

```
总预算  30 元     你说的
人数    1 人      我替你定的
餐段    午餐      我推断的
情绪    治愈 → sweet / warm / comfort
```

### 第 2 步 · 取数

按顺序调用麦当劳 MCP：

```
now-time-info → query-nearby-stores → query-meals
  → available-coupons / query-my-coupons / query-store-coupons
  → query-meal-detail（套餐展开）
  → list-nutrition-foods（低卡类愿望时）
  → calculate-price（逐单核价）
```

券池来自三处，缺一处就会漏掉最优组合：可领券、已持有券、门店券。

### 第 3 步 · 出方案

给 2-3 个方案，按**实付价**排序，每个方案必须带一句能对回用户原话的理由。说不清为什么推它的，不要推。

### 第 4 步 · 算两遍账

这是本技能的核心，不能省：

```
商品原价合计        xx.xx 元
AI 式口算           xx.xx 元   ← 面额最大的券直接减，不看门槛
官方口径            xx.xx 元   ← calculate-price 的真实返回
差额                ±x.xx 元
```

然后说明差额来源：哪张券没到门槛、哪张跨了渠道、哪张与其它券互斥。

**这一层的目的不是让数字好看，是让用户看见「算错的时候账单看起来完全正常」。**

### 第 5 步 · 等确认再下单

只有用户明确说「就这个」之后，才调用 `create-order`。支付链接交给用户自己处理，不要代付。

## 硬性约束

1. **不要让模型自己算钱**。所有金额必须来自 `calculate-price` 或本地确定性代码，不能靠心算给数。
2. **不要虚构菜单和价格**。拿不到 MCP 数据时，明说「以下为示例数据」，不要装作实时。
3. **不要替用户下单**。写操作一律等确认。
4. **不要暗示官方背书**。本技能是第三方作品，非麦当劳官方产品。

## 输出风格

- 说人话，不列参数表。
- 数字给到分，不要「大概 30 左右」。
- 差额要解释，不能只给一个数。
